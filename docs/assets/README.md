# Assets and provenance

[Back to the showcase](../../README.md)

These are original application assets and real Android captures. Screenshots are copied without visual retouching. The banner is a new SVG composition using the exact current mark geometry and the established navy, pearl, and lavender palette.

| Asset | Origin | Context |
| --- | --- | --- |
| `00-cover.svg` | Portfolio composition with the current original Véspera SVG paths | Navy/lavender presentation; no simulated product UI. |
| `vespera-calendar.svg` | Current source branding | Transparent crescent/folded-page mark with six date cells. |
| `vespera-calendar-icon.png` | Current source branding | Original icon on navy background. |
| `01-calendar.png` | Project documentation capture | 1.1.0 calendar header and mark; empty demonstration calendar. |
| `02-styles.png` | Project documentation capture | Earlier development build; the screen title was subsequently renamed from “Apariencia” to “Estilos”. The demonstrated presets remain available. |
| `03-photo-background.png` | 1.1.0 Compose UI review output | Synthetic gradient created by the test; opacity 40%, blur 75%. |
| `04-event-copies.png` | 1.1.0 Compose UI review output | Fictional “Ensayo” events after copying a day. Transient success message is part of the unmodified capture. |
| `05-account-backup.png` | 1.1.0 Compose UI review output | “journey” is a test identity, not a production account; recovery is pending connection in the isolated test. |

The images do not contain real appointments, personal photos, account credentials, or production data. UI-test captures can reflect scrolling or transient messages during a journey; they document actual app state rather than an idealized mockup.

The application includes licensed offline fonts; no font binaries are distributed here. System/browser fonts render the SVG banner. Dependency and font licenses remain applicable to the private application. Technology names identify the tools used and remain the property of their respective owners.

For application behavior and current scope, use the README and technical documents rather than assuming every historical screen is the current build.
